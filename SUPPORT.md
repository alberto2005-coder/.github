## English

Need help with one of these projects? Start here.

### Before asking

1. Read the repository `README.md`: installation, usage and common questions are usually covered there.
2. Check the open and closed issues of the project; your question may already be answered.
3. Make sure you are using the latest version or release available.

### Where to ask

| Type of question | Channel |
|---|---|
| Reproducible bug or unexpected behaviour | Open an issue with the **Bug report** template in the affected repository |
| Improvement idea or new feature | Open an issue with the **Feature request** template |
| Usage, installation or configuration question | Open an issue in the affected repository explaining the context |
| Security vulnerability | **Do not use public issues**: follow [`SECURITY.md`](SECURITY.md) |
| Anything else | Open an issue in the affected repository and describe the context |

### What to include

- Project and the version, release or commit you are using.
- Operating system, browser or runtime (for example, Node 20, Python 3.12, Windows 11).
- Exact steps to reproduce the problem.
- What you expected to happen and what actually happened.
- Complete error messages, stack traces or screenshots, if they add information.

The more specific your message, the faster the response.

### Response times

These are personal projects maintained in spare time. There is no service level commitment: replies are given on a best-effort basis, usually within a few days. No answer does not mean no interest; if your issue is still open and still relevant, you may politely bump it after a reasonable amount of time.

### What is not offered

- Support for private modifications of the code that are not in the repository.
- Help with third-party dependencies or services beyond pointing to their official support.
- Consulting, custom development or installations in corporate environments.

## Español

¿Necesitas ayuda con alguno de estos proyectos? Aquí tienes por dónde empezar.

### Antes de preguntar

1. Lee el `README.md` del repositorio: instalación, uso y preguntas frecuentes suelen estar ahí.
2. Revisa los issues abiertos y cerrados del proyecto; puede que tu duda ya esté resuelta.
3. Comprueba que usas la última versión o release disponible.

### Dónde preguntar

| Tipo de duda | Canal |
|---|---|
| Error reproducible o comportamiento inesperado | Abre un issue con la plantilla **Bug report** en el repositorio afectado |
| Propuesta de mejora o nueva función | Abre un issue con la plantilla **Feature request** |
| Duda de uso, instalación o configuración | Abre un issue en el repositorio afectado explicando el contexto |
| Vulnerabilidad de seguridad | **No uses issues públicos**: sigue [`SECURITY.md`](SECURITY.md) |
| Cualquier otra consulta | Abre un issue en el repositorio afectado explicando el contexto |

### Qué incluir en tu mensaje

- Proyecto y versión, release o commit que usas.
- Sistema operativo, navegador o entorno (por ejemplo, Node 20, Python 3.12, Windows 11).
- Pasos exactos para reproducir el problema.
- Qué esperabas que ocurriera y qué ocurrió en realidad.
- Mensajes de error completos, trazas o capturas, si aportan información.

Cuanto más concreto sea el mensaje, más rápida será la respuesta.

### Tiempos de respuesta

Estos proyectos son personales y se mantienen en el tiempo libre. No hay un compromiso de nivel de servicio: se responde en la medida de lo posible, normalmente en unos días. La falta de respuesta no implica falta de interés; si tu issue sigue abierto y sigue siendo relevante, puedes recordarlo con educación pasado un tiempo razonable.

### Qué no se ofrece

- Soporte para modificaciones privadas del código que no estén en el repositorio.
- Ayuda con problemas de dependencias o servicios de terceros más allá de indicar el enlace a su soporte oficial.
- Consultoría, desarrollos a medida o instalaciones en entornos corporativos.
