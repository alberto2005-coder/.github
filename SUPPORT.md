# Soporte

¿Necesitas ayuda con alguno de estos proyectos? Aquí tienes por dónde empezar.

## Antes de preguntar

1. Lee el `README.md` del repositorio: instalación, uso y preguntas frecuentes suelen estar ahí.
2. Revisa los issues abiertos y cerrados del proyecto; puede que tu duda ya esté resuelta.
3. Comprueba que usas la última versión o release disponible.

## Dónde preguntar

| Tipo de duda | Canal |
|---|---|
| Error reproducible o comportamiento inesperado | Abre un issue con la plantilla **Bug report** en el repositorio afectado |
| Propuesta de mejora o nueva función | Abre un issue con la plantilla **Feature request** |
| Duda de uso, instalación o configuración | Abre un issue en el repositorio afectado explicando el contexto |
| Vulnerabilidad de seguridad | **No uses issues públicos**: sigue [`SECURITY.md`](SECURITY.md) |
| Consulta privada o que no encaja en un issue | [albertoortixsanchez@gmail.com](mailto:albertoortixsanchez@gmail.com) |

## Qué incluir en tu mensaje

- Proyecto y versión, release o commit que usas.
- Sistema operativo, navegador o entorno (por ejemplo, Node 20, Python 3.12, Windows 11).
- Pasos exactos para reproducir el problema.
- Qué esperabas que ocurriera y qué ocurrió en realidad.
- Mensajes de error completos, trazas o capturas, si aportan información.

Cuanto más concreto sea el mensaje, más rápida será la respuesta.

## Tiempos de respuesta

Estos proyectos son personales y se mantienen en el tiempo libre. No hay un compromiso de nivel de servicio: se responde en la medida de lo posible, normalmente en unos días. La falta de respuesta no implica falta de interés; si tu issue sigue abierto y sigue siendo relevante, puedes recordarlo con educación pasado un tiempo razonable.

## Qué no se ofrece

- Soporte para modificaciones privadas del código que no estén en el repositorio.
- Ayuda con problemas de dependencias o servicios de terceros más allá de indicar el enlace a su soporte oficial.
- Consultoría, desarrollos a medida o instalaciones en entornos corporativos.
